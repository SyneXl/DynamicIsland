# Обновления нашей ветки

Канал: **https://github.com/SyneXl/DynamicIsland/releases**. Канал исходного автора не используется.

## Для пользователя

1. Скачать `DynamicIsland.exe` из последнего релиза. Приложение portable, .NET устанавливать не нужно.
2. Закрыть ранее запущенный остров, заменить его EXE новым и запустить. Старые сборки без обновлятора не могут обновиться сами. Если перенести EXE в другую папку, автозапуск нужно включить заново уже из новой копии.
3. Дальше обновления проверяются при запуске, раз в 30 минут и при открытии настроек. Принудительная проверка — «Настройки → Обновление».
4. Если есть новая версия, нажать «Обновить и перезапустить». Самостоятельно, без нажатия пользователя, EXE не заменяется.

В разделе «Обновление» есть отдельный пункт **«Что нового»**. До установки он показывает все опубликованные версии между установленной и целевой — от новых к старым, с отдельным заголовком каждой версии. Уже установленные версии, будущие версии, черновики и бета-теги в этот диапазон не входят. Пункты разных версий не смешиваются и не дублируются.

После подтверждённого запуска обновлённого EXE этот же диапазон сохраняется локально: его можно открыть после перезапуска и без интернета. Неуспешная установка и откат не становятся установленной историей. Свежая установка без известной предыдущей версии показывает описание своей версии, не выдумывая переход.

История хранится в `%LOCALAPPDATA%\DynamicIsland\Updates\history.json`: кэш доступного обновления отделён от последних восьми установленных диапазонов. Файл не зависит от расположения EXE и не удаляется вместе с временными GUID-каталогами. Повреждённый кэш не мешает запуску. Ошибка записи истории не откатывает успешно установленную программу.

Обычная фоновая проверка не скачивает всю историю. Описания загружаются при открытии «Что нового» или параллельно с загрузкой EXE. При недоступном API используется официальный Atom-канал того же репозитория с переходом по курсору `after`. Atom содержит также аннотированные Git-теги без опубликованного релиза: неизвестные архиву версии дополнительно проверяются по строке EXE и SHA-256 в файлах релиза. Например, существующие теги `v1.29.0` и `v1.31.0` не выдаются за опубликованные обновления. Если история загрузилась не полностью, это явно указано; установка проверенного EXE остаётся доступной.

В EXE включены описания из `docs/releases/v*.md` и индекс ранее опубликованных стабильных версий `docs/releases/published.json`. Будущий разрешённый workflow Release обновляет индекс запросом только на чтение перед сборкой; подготавливаемая текущая версия включается отдельно. Это позволяет новому помощнику восстановить правильный диапазон офлайн даже при переходе со старого обновлятора, который ещё не передавал описания, не включая исторические неудавшиеся теги.

С 1.31.0 новая версия показывается коротким уведомлением в островке, после которого остаётся боковой пузырёк. Нажатие на пузырёк повторяет уведомление и убирает его; нажатие на само уведомление открывает обновление. Непросмотренный пузырёк восстанавливается после перезапуска. Та же версия не уведомляет повторно.

Настройки остаются в прежнем `HKCU\Software\DynamicIsland`, а путь EXE не меняется: автозапуск продолжает работать. Папка EXE должна быть доступна пользователю для записи. Токены GitHub не требуются и в программу не встраиваются.

С 1.30.0 при ограничении или недоступности GitHub API проверка переключается на официальную страницу последнего стабильного релиза. Повторные проверки учитывают `Retry-After` и `X-RateLimit-Reset`, не расходуя исчерпанный лимит. Если старая 1.29.1 уже показывает ошибку из-за лимита API, первый переход на 1.30.0 можно выполнить вручную скачанным EXE.

## Проверка и восстановление

- Только опубликованный стабильный релиз с тегом `vMAJOR.MINOR.PATCH`, только `DynamicIsland.exe` из нашего репозитория.
- Для новой версии обязателен корректный `sha256:` digest из GitHub API либо из строки конкретного EXE на официальной странице файлов релиза. Хеш всей загрузки должен совпасть. Размер дополнительно проверяется, если опубликован в метаданных или заголовке ответа; в любом случае действует ограничение 512 МБ. Файл без digest не устанавливается.
- Загрузка идёт по HTTPS; зависшая передача прерывается через 30 секунд без данных. Повреждённая загрузка удаляется, работающий EXE не затрагивается.
- Проверенный EXE запускает отдельный режим помощника. Помощник ждёт завершения старого процесса с проверкой PID и времени его создания.
- Замена атомарная, рядом временно хранится предыдущий EXE. Новый процесс подтверждает, что создал WPF-интерфейс, сообщает PID и фактическую версию.
- При отсутствии подтверждения за 25 секунд помощник останавливает только созданный им процесс, возвращает прежний файл и запускает его. Другие экземпляры, проигрыватели и службы не останавливаются.
- Если завершившийся EXE ещё кратковременно удерживается Windows или проверкой антивируса, восстановление повторяется до 5 секунд. Резервный файл сохраняется до успешного переноса; исходный SHA-256 проверяется после восстановления.
- Журнал конкретной операции: `%LOCALAPPDATA%\DynamicIsland\Updates\<идентификатор>\result.json`. Общие ошибки: `%TEMP%\DynamicIsland.log`.
- Успешно завершённые временные каталоги удаляются после запуска, незавершённые старше недели — при последующей уборке. Каталоги с посторонними файлами и ссылки не удаляются.
- Временные файлы не заменяют резервную копию исходников; исходники доступны по тегу релиза.

## Как выпускать следующую версию

Сначала предоставить пользователю локальную сборку для проверки. Публикация на GitHub выполняется только после отдельного явного разрешения на релиз этих изменений. Запрос доработки и разрешения на прежние релизы такого согласия не заменяют. До разрешения не отправлять версионные теги, не запускать `Release` и не создавать релизы, включая черновики и prerelease.

1. Внести и проверить изменения, поднять `<Version>` в `DynamicIsland.csproj`, например до `1.29.1`.
2. Создать `docs/releases/v1.29.1.md` с короткими пунктами изменений.
3. После проверки локальной сборки пользователем и его явного разрешения на релиз закоммитить и отправить изменения в **свой** `main`.
4. Создать и отправить только новый тег:

```powershell
git tag -a v1.29.1 -F docs/releases/v1.29.1.md
git push origin main
git push origin v1.29.1
```

Не использовать `git push --tags`: теги исходного проекта не являются релизами нашей ветки.

GitHub Actions проверит тесты, соберёт self-contained EXE, откроет его в изолированном smoke-режиме, загрузит EXE и SHA256SUMS.txt в черновик релиза, сверит digest и только затем опубликует релиз. Несовпадение версии/тега и повторный выпуск существующего релиза завершаются ошибкой вместо перезаписи.

## UI review

| Before | After | Why |
| --- | --- | --- |
| Страница обновления удалена | Версия и переход в настройках, канал собственного форка | Друзья получают только нашу сборку |
| Нет первого релиза | Спокойное «пока без релизов» | Это не ошибка сети |
| Загрузка без объяснения | Кольцо, проценты и объём в минимальной карточке | Прогресс понятен и не захламляет меню |
| Длинные примечания увеличивали остров | Прокрутка в ограниченной области | Размер островка остаётся ограниченным |
| Показывалось только описание последнего релиза | Все пропущенные опубликованные версии в диапазоне, с числовой сортировкой и заголовками | Переход через несколько версий не теряет изменения |
| Список занимал основную страницу и исчезал после обновления | Отдельный пункт «Что нового» и вложенная страница; установленный диапазон сохранён офлайн | Основной экран короткий, описание доступно позже |
| Немедленный запуск второго EXE | Ожидание выхода и подтверждение нового интерфейса | Не конфликтует single-instance mutex |
| Пузырёк обновления 38×34, внутренняя сетка шире области с отступами; значок 17×17 смещается при округлении | Круг 34×34, сетка 32×32, значок 18×18 | Одинаковые отступы со всех сторон; центрирование сохраняется при наведении, нажатии и масштабировании |

Проверки: `--release-notes-tests <папка>` (поддельная сеть и отдельный кэш), `--release-notes-readonly <папка>` (только GET публичного канала), `--update-handoff-tests <локальный EXE> <папка>` (изолированные копии EXE, подтверждение запуска, откат и журнал).

Источники: [список релизов и пагинация GitHub REST API](https://docs.github.com/en/rest/releases/releases#list-releases), [проверка файлов релиза](https://docs.github.com/en/rest/releases/assets), [официальный Atom-канал форка](https://github.com/SyneXl/DynamicIsland/releases.atom). Курсор `?after=v1.31.0` и конец списка проверены запросами только на чтение.
