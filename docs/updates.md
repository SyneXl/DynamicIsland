# Обновления нашей ветки

Канал: **https://github.com/SyneXl/DynamicIsland/releases**. Канал исходного автора не используется.

## Для пользователя

1. Скачать `DynamicIsland.exe` из последнего релиза. Приложение portable, .NET устанавливать не нужно.
2. Закрыть ранее запущенный остров, заменить его EXE новым и запустить. Старые сборки без обновлятора не могут обновиться сами. Если перенести EXE в другую папку, автозапуск нужно включить заново уже из новой копии.
3. Дальше обновления проверяются при запуске, раз в 30 минут и при открытии настроек. Принудительная проверка — «Настройки → Обновление».
4. Если есть новая версия, нажать «Обновить и перезапустить». Самостоятельно, без нажатия пользователя, EXE не заменяется.

Настройки остаются в прежнем `HKCU\Software\DynamicIsland`, а путь EXE не меняется: автозапуск продолжает работать. Папка EXE должна быть доступна пользователю для записи. Токены GitHub не требуются и в программу не встраиваются.

## Проверка и восстановление

- Только опубликованный стабильный релиз с тегом `vMAJOR.MINOR.PATCH`, только `DynamicIsland.exe` из нашего репозитория.
- Для новой версии обязательны корректный `sha256:` digest из GitHub API и совпадение размера файла. Файл без digest не устанавливается.
- Загрузка идёт по HTTPS; зависшая передача прерывается через 30 секунд без данных. Повреждённая загрузка удаляется, работающий EXE не затрагивается.
- Проверенный EXE запускает отдельный режим помощника. Помощник ждёт завершения старого процесса с проверкой PID и времени его создания.
- Замена атомарная, рядом временно хранится предыдущий EXE. Новый процесс подтверждает, что создал WPF-интерфейс, сообщает PID и фактическую версию.
- При отсутствии подтверждения за 25 секунд помощник останавливает только созданный им процесс, возвращает прежний файл и запускает его. Другие экземпляры, проигрыватели и службы не останавливаются.
- Журнал конкретной операции: `%LOCALAPPDATA%\DynamicIsland\Updates\<идентификатор>\result.json`. Общие ошибки: `%TEMP%\DynamicIsland.log`.
- Успешно завершённые временные каталоги удаляются после запуска, незавершённые старше недели — при последующей уборке. Каталоги с посторонними файлами и ссылки не удаляются.
- Временные файлы не заменяют резервную копию исходников; исходники доступны по тегу релиза.

## Как выпускать следующую версию

1. Внести и проверить изменения, поднять `<Version>` в `DynamicIsland.csproj`, например до `1.29.1`.
2. Создать `docs/releases/v1.29.1.md` с короткими пунктами изменений.
3. Закоммитить и отправить изменения в **свой** `main`.
4. Создать и отправить только новый тег:

```powershell
git tag -a v1.29.1 -F docs/releases/v1.29.1.md
git push origin main
git push origin v1.29.1
```

Не использовать `git push --tags`: теги исходного проекта не являются релизами нашей ветки.

GitHub Actions проверит тесты, соберёт self-contained EXE, откроет его в изолированном smoke-режиме, загрузит EXE и SHA256SUMS.txt в черновик релиза, сверит digest и только затем опубликует релиз. Несовпадение версии/тега и повторный выпуск существующего релиза завершаются ошибкой вместо перезаписи.

## UI review

| Before | After | Why |
| --- | --- | --- |
| Страница обновления удалена | Версия и переход в настройках, канал собственного форка | Друзья получают только нашу сборку |
| Нет первого релиза | Спокойное «пока без релизов» | Это не ошибка сети |
| Загрузка без объяснения | Кольцо, проценты и объём в минимальной карточке | Прогресс понятен и не захламляет меню |
| Длинные примечания увеличивали остров | Прокрутка в ограниченной области | Кнопка установки остаётся доступной |
| Немедленный запуск второго EXE | Ожидание выхода и подтверждение нового интерфейса | Не конфликтует single-instance mutex |
