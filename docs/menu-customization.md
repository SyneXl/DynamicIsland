# Пункты меню

Редактор находится в **Оформление → Пункты меню**. Переключатели скрывают
необязательные пункты, перетаскивание мышью меняет порядок. Скрытые пункты остаются в
редакторе: их можно переставлять и возвращать на выбранное место.

- **Настройки**, **Оформление** и **Закрыть остров** всегда включены. Их порядок
  тоже разрешено менять. Даже если скрыть всё остальное, доступ к редактору и
  завершению приложения остаётся.
- Изменения применяются и сохраняются сразу. Кнопка **Сбросить** возвращает
  только исходное меню, не трогая остальные настройки и интеграции.
- Скрытие — не отключение функции. Уже запущенный таймер, запись OBS, погода,
  полка и автопинг Codex продолжают работать как раньше. Для управления активной
  задачей остаются её обычные индикаторы/пузырьки, а пункт можно вернуть в редакторе.
- Строку можно тянуть за название или шеститочечную ручку справа. У краёв
  список прокручивается сам. Переключатель видимости не начинает перетаскивание.
- До отпускания мыши перестановка — только предпросмотр; сохранение выполняется
  один раз при завершении. **Esc**, потеря захвата и уход со страницы отменяют жест.
  Ошибка записи возвращает предыдущий порядок в меню и редакторе.
- **Alt+↑ / Alt+↓** на сфокусированном переключателе или ручке перемещают строку
  с клавиатуры. **Esc** вне перетаскивания возвращает к оформлению.
- Редактор и длинное меню прокручиваются внутри островка. Колесо над ними,
  включая заголовок и границы прокрутки, не меняет громкость
  и не переключает медиаисточники. В оформлении колесо над размером/отступом
  сохраняет прежний смысл; в остальной области прокручивает страницу.
- Названия пунктов используют тот же встроенный SF Pro Text и размер 13,5 px,
  что и основное меню. Верхние пояснения и постоянная подпись снизу убраны;
  высота страницы без них — 408 px вместо 478 px. Сообщение появляется только
  при ошибке сохранения, не резервирует пустое место и исчезает после успешной записи.

## Хранение и расширение

`MenuLayout.cs` — каталог стабильных ID, обязательность, порядок по умолчанию,
чистая модель изменения и нормализация сохранённых данных.
`MainWindow.MenuLayout.cs` отвечает только за отображение/действия редактора.
Исходные кнопки главного меню сохраняют экземпляры, Click-маршруты и счётчики.
При переключении видимости список не пересоздаётся целиком.

Настройки хранятся одной JSON-строкой **MenuLayout** в
`HKCU\Software\DynamicIsland`. Сначала выполняется запись, затем меняется
снимок в памяти. При ошибке записи сохраняется предыдущий вид и появляется
короткое сообщение. Повторное действие может сохранить настройку заново.

Формат: `Version: 2`, `Entries: [{ Id, Visible }]`. Порядок массива задаёт
порядок меню. Поддерживаются пустая первая установка, повреждённая строка,
неподдерживаемая версия, неверные типы, дубли, неизвестные/пропущенные ID и
попытка скрыть обязательные пункты. Восстановление при чтении не перезаписывает
реестр. Исходные флаги остальных функций не меняются.

Для новой страницы:

1. Добавить определение с постоянным ID в `MenuLayout.Catalog`.
2. Добавить кнопку с таким же `Tag` и её обычный обработчик в `MenuRows`.
3. Настроить представление страницы как обычно.

Редактор, скрытие, сохранение, нормализация и прокрутка подхватят её сами.
При несовпадении ID каталога/маршрутов конструктор явно сообщает об ошибке.
Zapret по умолчанию стоит после OBS, перед полкой и погодой. В старых меню v1,
где интеграция автоматически попала после выхода или сохранился прежний порядок
по умолчанию, её положение исправляется при чтении. Скрытые пункты остаются
скрытыми. Произвольная пользовательская сортировка не сбрасывается; сохранение
в v2 фиксирует и намеренное перемещение Zapret в самый низ. Меню v1 без этого
пункта получает его после OBS, а не после выхода.

Остальные новые ID добавляются в конец сохранённого списка без сброса
сортировки. Неизвестные ID при чтении игнорируются; последующее сохранение
канонизирует список для текущей версии приложения.

## UI review

| Before | After | Why |
| --- | --- | --- |
| Десять пунктов с новой интеграцией, длина растёт с каждой функцией | Только выбранные пункты, высота по содержимому | Убирает ненужное без пустого места |
| По две стрелки на каждую строку | Одна ручка, перетаскивание за название и Alt+↑/↓ | Меньше шума, прямое управление и клавиатурный доступ |
| Любое скрытие могло бы запереть пользователя | Три обязательных маршрута, явная отметка «Всегда» | Настройки, восстановление меню и выход доступны всегда |
| Обычная светлая полоса Windows на чёрном островке | Узкий полупрозрачный scrollbar | Не выбивается из существующего оформления |
| Колесо вне строк могло менять громкость | Прокрутка перехватывается всей страницей | Исключает побочные действия во время настройки |
| Названия в редакторе — 12 px при 13,5 px в меню | SF Pro Text 13,5 px в обоих местах | Единая типографика без замены шрифта |
| Мелкие инструкции сверху и постоянная подпись снизу | Только заголовок, сброс и список; ошибка — по необходимости | Меньше шума и 70 px лишней высоты |

## Проверки

```powershell
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -p:MediaTestApi=true -- --media-regressions
```

Тесты модели покрывают нормализацию, перезапуск, будущую интеграцию и 600
воспроизводимых смешанных операций. WPF-проверки используют настоящие кнопки,
панели и обработчики; только сохранение подменено на память, чтобы не менять
реестр пользователя. Проверены скрытие всех необязательных пунктов, сохранение
экземпляров кнопок, возврат скрытого пункта, ошибка записи, новый экземпляр окна,
сброс, прокрутка и доступ к последней строке. Тесты не отправляют реальные
медиа-команды и запросы автопинга.
