# Throne — интеграция 1.30.0

## Первый запуск

1. Нужна Throne с API: **1.4.0-beta.2 и новее**. Проверена настоящая **1.4.0-beta.4**.
2. В Throne открой **Настройки → Настройки интеграции → Throne API** и включи API. Локального доступа достаточно; доступ из локальной сети включать не нужно.
3. В островке открой **Throne** и нажми круглую стрелку обновления. Ключ и порт читаются из конфигурации Throne автоматически, без копирования ключа в буфер или реестр островка.

Если программа и её настройки найдены, а API просто выключен, показывается только инструкция подключения. «Выбрать Throne.exe» появляется, если автоматический поиск не нашёл программу. Выбор папки настроек появляется только при проблеме с обнаружением конфигурации или подключением к API. После успешного подключения обе кнопки скрываются.

## Управление

- Круглая кнопка запускает или останавливает подключение через API. Островок не завершает процессы и не меняет настройки TUN, системного прокси, подписок или автозапуска Throne.
- Выбор группы меняет список серверов и выбор для следующего запуска, но не переключает работающий VPN сам по себе.
- Выбор сервера при включённом подключении переключает сервер; при выключенном только запоминает выбор.
- «Проверить пинг» использует штатный URL-тест Throne, не ICMP. По завершении включается сортировка по задержке. Можно вернуть исходный порядок или остановить свой тест. Недоступные серверы не показываются с отрицательным пингом.
- Есть поиск по серверам. Esc очищает поиск; повторное нажатие возвращает на главную страницу Throne.
- Переходные состояния берутся из API. Ответ `202` не считается подтверждением включения. Повторные команды во время переключения блокируются.

## Меню и обнаружение

Throne располагается рядом с Zapret. Без найденной API-совместимой версии пункт автоматически скрыт. Это автоматическое состояние обновляется и после последующей установки беты; явное включение или скрытие в редакторе меню имеет приоритет и сохраняется при перезапуске. Перестановка остальных пунктов не отключает автоматическое обнаружение.

Обнаружение использует путь запущенного процесса, установочные записи Windows и стандартные каталоги. Поддержка API определяется не только по номеру версии файла: разные беты имеют одинаковый `FileVersion`. Проверяется наличие реализации протокола в исполняемом файле. Чтение конфигурации — read-only SQLite с поддержкой живого WAL; база Throne не переписывается и не копируется без WAL.

## Обновление Throne

При отсутствии подходящей версии ручное включение пункта меню открывает страницу обновления. Кнопка ищет актуальный Windows universal installer среди стабильных и бета-релизов официального `throneproj/Throne`, а не закрепляет beta.4 навсегда.

При ограничении публичного GitHub API используется официальная страница Releases с SHA-256 конкретного файла. Скачивание идёт в настоящую системную папку **«Загрузки»** (включая перенесённую пользователем), во временный `.part`. Проверяются SHA-256, размер при наличии и заголовок EXE. Существующие файлы не перезаписываются. Отмена и ошибка убирают только свой временный файл.

После загрузки появляется отдельная кнопка **«Запустить установщик»**. Автоматического запуска нет; перед ручным запуском хеш проверяется повторно. Запуск запрашивает права администратора через UAC. Пока установщик работает, повторный запуск заблокирован, но интерфейс островка не блокируется.

После завершения установщика островок повторно проверяет фактическую установленную версию. Сам выход установщика не считается успехом. Если обнаружена версия с API, вся строка об установщике и кнопка запуска исчезают, даже если API пока выключен. Файл в «Загрузках» остаётся. При открытой странице недоступная интеграция перепроверяется не чаще одного раза в пять секунд, поэтому установка извне и включение API тоже подхватываются без перезапуска островка. Для работающего подключения сохраняется лёгкий запрос статуса раз в две секунды; сканирования всех дисков нет.

## Реализация и визуальные решения

Протокол — `throne-api/1`: TCP, HMAC-SHA256, ChaCha20-Poly1305, случайные hello и отдельные ключи направлений. Подключение ограничено loopback. На Windows 10 используется управляемая криптография Bouncy Castle, поскольку штатный ChaCha20 этой версии Windows недоступен.

| Before | After | Why |
| --- | --- | --- |
| Нет Throne в островке | Отдельная компактная страница рядом с Zapret | Интеграция не засоряет настройки |
| Только внешнее окно клиента | Круглая play/pause, две строки выбора | Сохраняет язык интерфейса островка |
| Длинный список серверов | Поиск, задержки, переключаемая сортировка | Проще находить сервер без лишней информации |
| Фиксированная большая панель | Высота списков по содержимому, прокрутка для длинных списков | Короткие списки не оставляют пустую панель |
| Возможное постоянное сканирование | Обнаружение при запуске/открытии/обновлении; ограниченная перепроверка недоступного API только в открытом разделе | Нет полного обхода дисков и постоянного фонового сканирования |
| Кнопка установщика оставалась после установки | Весь блок скрывается при обнаружении совместимой версии | Перезапуск островка не требуется |
| Запуск полагался на манифест установщика | Явный `runas` после повторной проверки SHA-256 | Права администратора запрашиваются независимо от манифеста |

```powershell
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --throne-tests C:\Temp\island-throne-tests
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --menu-window-test C:\Temp\island-menu-tests
```

Отдельный тест настоящей беты выполнялся в изолированной папке данных, с отдельным ключом/портом, без TUN и системного прокси. Запускались только тестовые loopback-профили; основной пользовательский Throne не переключался. Установщик из официального релиза полностью скачан и проверен, но не запускался.
