# Codex: лимиты и автозапуск пятичасового окна

## Использование

Открыть меню острова → **Codex**. Здесь только остаток 5-часового и недельного
лимита, время сброса, ручное обновление и переключатель автопинга.
По умолчанию автопинг **выключен**; выбор сохраняется в существующем ключе
`HKCU\Software\DynamicIsland`, значение `CodexAutoPing`.

Нужен установленный Codex со входом в подписочный аккаунт. Используется его
локальный `codex app-server --stdio`, не отдельный API key и не UsageLoop.
Codex сам обрабатывает авторизацию. Остров не читает `auth.json`, не копирует
токены, не меняет конфигурацию Codex и не пишет содержимое его ответов в лог.

При выключенном переключателе данные читаются при открытии этого пункта или
нажатии «Обновить». Включённый режим проверяет лимиты в фоне, обычно раз в
5 минут; перед известной границей интервал сокращается. Работает, пока остров
запущен и компьютер не спит. После сна данные проверяются заново, пропущенные
пинги не воспроизводятся задним числом.

Пинг — **один короткий реальный запрос**, расходующий небольшую часть квоты,
а не увеличение или обход лимита. Он нужен, чтобы начать новое окно, пока
пользователь ничего не спрашивает. Активное окно не перезапускается.

## Исследование исходников

Репозиторий пользователя действительно клонирован целиком через `git clone
--depth 1 https://github.com/benthompsondev/usageloop`, затем изучены
`src/sentinel/classifier.py`, `quota.py`, `trigger.py`, `models.py`,
`protocol.py`, `transport.py`, `providers.py`.
Зафиксированная ревизия: **45fdf593d2429c25c32b81acafc89a155a911ed8**.
Его скрипты и установщик не запускались.

Основная полезная идея — наблюдать за абсолютным `resetsAt`:

- Фиксированное время при движении часов: окно уже началось.
- Время движется вместе с часами и остаётся примерно в 5 часах впереди:
  окно пока ждёт первого запроса.
- Полная шкала сама по себе не доказывает ни сброс, ни запуск окна.

Из репозитория взяты функциональная схема, высокая степень уверенности
(4 наблюдения за 30 секунд), минимальный ephemeral-запрос и осторожный
выбор модели. Реализация написана на C#, без Python, фонового UsageLoop,
его интерфейса, аналитики, обновлений и обращения к GitHub во время работы.
MIT attribution включён в `Notices/UsageLoop-MIT.txt` и ресурс сборки.

Дополнительно протокол сверен с официальным описанием
[Codex app-server](https://learn.chatgpt.com/docs/app-server) и JSON-схемами,
которые сгенерированы установленным CLI `0.163.0-alpha.10.2` через
`codex app-server generate-json-schema`. Только stable handshake:
`experimentalApi=false`. Из ответов используется `rateLimitsByLimitId`,
при его отсутствии — legacy `rateLimits`; слоты определяются по длительности,
а не по названию `primary`. `usedPercent` означает **израсходовано**.

## Защита от лишних запросов

1. Прочитать квоту через `account/rateLimits/read` — без inference.
2. Подтвердить профиль окна четырьмя наблюдениями с интервалом 10 секунд.
   Неизвестные, противоречивые, устаревшие данные и смена аккаунта запрещают
   пинг. Ранее подтверждённое фиксированное окно обходится одним чтением.
3. Разрешить запуск только для официального `codex`, ровно 300 минут,
   0% израсходовано, `ordinaryUsageAllowed=true`, без блокировки, при известной
   будущей недельной квоте с расходом меньше 99%.
4. После ранее подтверждённого сброса выждать ещё 60 секунд. Если истории
   ещё нет, включение пользователем позволяет запустить достоверно незапущенное
   окно. Новое окно не выдумывается из локального таймера.
5. Из актуального `model/list` выбрать известную лёгкую текстовую модель:
   `gpt-6-luna`, затем `gpt-5.6-luna`, с минимальным поддерживаемым effort.
   Скрытые/заменённые модели запрещены. Нет подходящей — нет запроса;
   дорогого или произвольного fallback нет. Стандартный service tier.
6. После проверки модели снова прочитать квоту: обычная работа пользователя
   могла уже начать окно. Проверить переключатель ещё раз.
7. **До** потенциальной отправки атомарно сохранить reservation в
   `%LOCALAPPDATA%\DynamicIsland\Codex\state.json`. В журнале только SHA-256
   идентификатора аккаунта, граница окна и статус; исходного account ID нет.
   Межпроцессный lock + flush-to-disk + atomic replace. Повреждённый журнал
   блокирует автоматическую отправку, а не обнуляет защиту от дублей.
8. Создать ephemeral thread в отдельном пустом workspace, `sandbox=read-only`,
   `approvalPolicy=never`, и ровно один `turn/start`: «Reply only OK.
   Do not use tools.» Обычные чаты пользователя не затрагиваются.
   Серверные запросы инструментов/подтверждений клиент отклоняет.
9. Завершённый turn ещё не успех: заново наблюдать квоту. Успех сохраняется
   лишь после фиксированного времени сброса того же окна/аккаунта.
   Сбой/таймаут/неподтверждённый результат не повторяется автоматически
   для той же возможности, в том числе после перезапуска или выкл/вкл.

## UI: до / после

| До | После |
| --- | --- |
| Лимиты Codex не отображались | Отдельный пункт меню, без новых строк в настройках |
| Требовался отдельный UsageLoop | Собственный компактный WPF-экран 320×336 |
| Ручной первый запрос | Опциональный автопинг с постоянной защитой от дублей |
| Нет проверяемого статуса сброса | Серверное время + обратный отсчёт; неизвестное отмечено явно |

Никаких моделей, логинов, токенов, графиков истории или остальных функций
UsageLoop в интерфейсе. Шкалы монохромные; цвета и анимация меню существующие.
Кинорежим, переключение источников, погода и перемотка MPC-BE не менялись.

### Упрощение экрана, 20 октября 2026

| Before | After | Why |
| --- | --- | --- |
| «5 часов · осталось», «Неделя · осталось» | «5 часов», «Неделя» | Убрать повторяющуюся подпись и разделители |
| «Сброс 08:09 · через 47 м» | «Сброс через 47 мин» | Один факт в строке; точная дата и время доступны по наведению |
| «Автопинг после сброса» + постоянная строка ожидания | «Автопинг» без обычного статуса | Состояние уже видно на переключателе и в отсчёте |
| Фиксированная высота | Высота по содержимому | Нет пустоты после скрытой строки; ошибки расширяют карточку |

Ошибки, загрузка и неизвестные сообщения не скрываются. Сокращение текста —
только слой отображения: классификация окон, отправка, журнал и настройки
автопинга остаются прежними. Проценты по-прежнему означают остаток; это также
указано в подсказке и accessibility name.

## Проверки

`dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release`
включает прежние 105 проверок и новые тесты парсинга, классификации,
моделей, постоянного журнала, перезапуска, защитных условий, UI и NDJSON.
Переход через сброс и сам пинг тестируются на изолированных фикстурах.
Транспортный тест запускает собственный дочерний процесс-имитатор app-server,
прогоняя настоящий код клиента, пагинацию и отказ от server-requested tools.

`dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --codex-probe`
проверяет **реальное** соединение с установленным Codex: четыре чтения квоты
за 30 секунд, классификация окна и каталог моделей, без `thread/start` и
`turn/start`. Вывод очищен от account ID.
Пятичасовой реальный цикл и платный/подписочный inference во время разработки
не запускались. Снимки UI используют явно заданные тестовые данные.

Билд: `dotnet publish DynamicIsland.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o publish/codex-limits`.
Запуск `DynamicIsland.exe --smoke-test <absolute-result.json>` проверяет реальный
WPF HWND без внешних сервисов и без остановки уже работающего острова.
