# Zapret в островке

Отдельный пункт **Zapret** в меню, по умолчанию после OBS, перед полкой и погодой.
Прежнее автоматическое добавление ниже выхода мигрирует без сброса скрытых пунктов;
произвольная ручная сортировка сохраняется. Его можно скрыть или переставить в
**Оформление → Пункты меню**. Скрытие не останавливает службу.

## Использование

1. Открой Zapret. В фоне начнётся поиск распакованных копий на всех готовых
   локальных и съёмных дисках. Известная папка и папка действующей службы
   проверяются первыми. Поиск можно остановить и запустить повторно.
2. В строке **Папка zapret** выбери нужную копию. Есть ручной выбор папки.
   Отображаются версия и полный путь; совпадающие имена папок не объединяются.
3. Выбери **Стратегию по умолчанию**. Выбор запоминается отдельно для каждой
   копии и сам по себе ничего не запускает и не перезапускает.
4. **Включить** устанавливает и запускает службу `zapret` с автоматическим
   запуском Windows. Понадобится обычное подтверждение UAC. Сам островок
   постоянно с правами администратора не работает.
5. Круглая кнопка **▶ / Ⅱ** включает или выключает Zapret одним нажатием,
   без дополнительного подтверждения внутри островка. Системный запрос прав
   Windows остаётся. Выключение останавливает и удаляет только службу Zapret
   и завершает подтверждённые процессы из установок Zapret.
6. При работающей другой копии/стратегии **Применить** заменяет единственную
   службу выбранной конфигурацией. Остановленная служба предлагает **▶** для
   повторного запуска; удаление её остатков доступно отдельной кнопкой.

**Важно:** по последующей просьбе пользователя обычное выключение больше
**не повторяет глобальный `2. Remove Services`**. `WinDivert` и `WinDivert14`
могут быть общими с VPN: островок их не останавливает, не удаляет и не ждёт,
независимо от того, в чьей папке лежит драйвер. Их `RUNNING`/`STOP_PENDING` не
влияет на статус Zapret, результат выключения или проверку конфликта конфигурации.
Для одного только драйвера не появляется кнопка очистки и сообщение об ошибке.

Архивы не распаковываются; сетевые диски, переходы по ссылкам/junction и
недоступные папки не обходятся. В конце поиска виден счётчик недоступных папок.
Ручной выбор позволяет указать папку, доступную текущему пользователю.
Сканирование не запускается при старте островка и не повторяется по таймеру.

## Исследованный контракт

Изучены локальные `C:\zapret\service.bat` и пять вложенных старых копий,
версии 1.9.0b, 1.9.5, 1.9.7b, 1.9.8c, 1.10.2, 1.10.4 — 119 стратегий.
Репозиторий скачан целиком через git; исследованный commit:
[`176f56dc3f11ce5915c26abcdde903f93d835b64`](https://github.com/Flowseal/zapret-discord-youtube/blob/176f56dc3f11ce5915c26abcdde903f93d835b64/service.bat).
Текущий локальный `service.bat` совпал с ним по SHA-256.
Полный обход доступных локальных дисков также нашёл ещё пять копий в других
папках и резервной копии на диске D: — всего 11 распакованных установок.
Нативный парсер дополнительно проверен на всех 213 стратегиях этих 11 копий.

| Original `service.bat` | Реализация островка | Примечание |
| --- | --- | --- |
| `load_user_lists` | Создание трёх отсутствующих пользовательских списков | Существующие списки не перезаписываются |
| `game_switch_status`, разбор выбранного BAT | `ZapretStrategyParser` | Старые и новые флаги Game Filter, TCP/UDP, пользовательские диапазоны, повторяемые параметры и `^!` |
| `tcp_enable` | `netsh interface tcp set global timestamps=enabled` | То же конечное состояние |
| `net stop zapret`, `sc delete zapret` | Остановка и удаление с ожиданием SCM | Ошибки не маскируются |
| `sc create ... start= auto` | Та же служба, выбранный `bin\winws.exe` и аргументы | Абсолютные пути и Windows-экранирование |
| Описание, `sc start`, реестровая отметка стратегии | Описание, отметка, запуск и проверка | Отметка сохраняется перед запуском для диагностики неудачного старта |
| `2. Remove Services` (исторический исходник) | Только zapret и подтверждённые процессы Zapret | Намеренно изменено по новой просьбе: общие драйверы и VPN не затрагиваются |

Батники не исполняются: не нужны консольные окна, имитация нажатий, хрупкий
разбор локализованного вывода или запуск проверки обновлений утилиты. Нет
обращений к GitHub при работе этой интеграции. Статус читается через Windows
SCM, реестр службы и список процессов; опрос раз в две секунды только при
открытой странице/видимом пункте Zapret.

Обнаружена проблема исходного меню со сторонними BAT-именами на кириллице:
вывод PowerShell при `chcp 437` может портить имя. Островок перечисляет файлы
через Unicode API, поэтому не зависит от этого меню и кодовой страницы.

## Согласованность и ошибки

- Неверная/удалённая папка, неизвестная подстановка BAT и отсутствующие файлы
  стратегии останавливают установку до удаления существующей службы.
- Повреждённое сохранение не вызывает автоматический запуск. Исчезнувшая
  сохранённая стратегия требует нового выбора, а не подменяется молча.
- Перед повышением прав фиксируются выбранная папка, стратегия и идентичность
  конфигурации служб; helper проверяет их повторно. Изменённые файлы или внешняя
  смена службы требуют обновить статус и повторить действие. Отпечаток включает
  только сохранённую конфигурацию службы Zapret: путь/параметры, стратегию и тип
  запуска, без драйверов других утилит. Пути живых процессов в него не входят — их видимость
  различается до и после UAC, а завершение/перезапуск процесса не меняет конфигурацию.
- Повышенный helper изменяет только одну службу — `zapret`. Изменять службы
  драйверов запрещено и на уровне нативного backend. Запрос одноразовый, с GUID,
  сроком жизни, SHA-256 и блокировкой
  исходных файлов. Параллельные операции сериализованы глобальным mutex.
- Отмена UAC не меняет службы. Пока операция выполняется, повторный запуск
  и изменение выбранных папки/стратегии заблокированы. На кнопке отображается
  индикатор выполнения. Чтение статуса до и после операции ожидается целиком;
  запоздалый опрос не может затереть итоговое состояние старым снимком.
- Путь процесса читается через
  [QueryFullProcessImageName](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew)
  с `PROCESS_QUERY_LIMITED_INFORMATION`, а не чтением модулей процесса.
  PID службы используется только в стабильных состояниях, допустимых для
  [QueryServiceStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryservicestatusex).
  Одного имени `winws.exe` недостаточно: нужен путь зарегистрированной службы
  либо `bin\winws.exe` в папке с проверяемым контрактом `service.bat`.
  Sing-box и одноимённые процессы другой программы не затрагиваются.
- Перед принудительным завершением путь проверяется повторно по **тому же
  дескриптору**, который используется для завершения, без повторного открытия по
  потенциально переиспользованному PID. Деревья процессов не завершаются.
- Служба получает запрос нормальной остановки; ожидание короткое и ограниченное.
  При зависании завершаются только подтверждённые процессы Zapret. Успех требует
  отсутствия процессов и удалённой/помеченной на удаление службы. Последний случай
  уже исключает автозапуск и не требует ожидания чужого читающего дескриптора.
  Остановленная служба с оставленным автозапуском не считается полным успехом.
- Если реальный процесс остался или проверка отказала в доступе, выключение не
  выдаётся за подтверждённый успех. В UI — короткая ошибка только про Zapret;
  технические детали остаются в trace операции.
- Неудачный старт не отображается как успех: новая служба может остаться
  установленной, но остановленной. Её можно удалить или повторно применить
  стратегию. Автоматического восстановления прежней службы нет.
- TCP timestamps, как и в оригинальном Remove Services, назад не выключаются.
- `ZapretPreferences` в `HKCU\Software\DynamicIsland` хранит только выбор
  папки/стратегии. Последний результат операции —
  `%LOCALAPPDATA%\DynamicIsland\zapret-last-operation.json`.

## Проверки

```powershell
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --menu-window-test C:\PATH\ui-results
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --zapret-tests C:\PATH\zapret-results
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --zapret-discovery C:\PATH\discovery.json
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --zapret-identity-tests C:\PATH\identity-results
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -- --zapret-isolation-tests C:\PATH\isolation-results
```

Запуск/удаление проверены с подменённым SCM, без изменения живых служб.
Дополнительная нативная no-op проверка выполняется лишь когда реальная служба
отсутствует и процессов WinWS нет: быстрый результат при фактическом
`WinDivert STOP_PENDING` проверяется без переключения VPN.
Исходный FOR-парсер оригинальных батников отдельно запускается в изолированных
копиях с удалёнными управляющими командами; его argv сравнивается с нативным
парсером, включая режимы Game Filter. Для кириллических имён выбор передаётся
явно, минуя повреждающее кодировку исходное перечисление; сам FOR-парсер
аргументов сохраняется. Проверки WPF используют реальные контролы и HWND,
но не принимают UAC и не отключают действующий общий драйвер.

## UI review

| Before | After | Why |
| --- | --- | --- |
| Консольный выбор номера стратегии | Папка, стратегия и одна основная кнопка | Минимум действий без повторения всего service.bat |
| Несколько версий с одинаковыми именами | Версия и путь каждой копии | Выбор без молчаливой подмены |
| Смена выбора могла бы неожиданно перезапустить сеть | Выбор отдельно от «Применить» | Предсказуемое действие |
| Текстовая кнопка и повторное подтверждение | Круглая ▶ / Ⅱ, один клик и только UAC Windows | Прямое управление без лишних шагов |
| Параграфы о службах, глобальности и смене стратегии в обычном состоянии | Статус, короткая подпись, папка и стратегия; технические детали в подсказках | Меньше визуального шума |
| Старое сообщение об ошибке сохранялось после обновления | Явное обновление убирает старую ошибку; успешное действие не добавляет текст | Страница отражает текущий результат |
