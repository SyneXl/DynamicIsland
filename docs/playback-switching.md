# Устойчивое переключение воспроизведений

Исправления по результатам аудита от 20 октября 2026. Идентификаторы F1–F9
соответствуют `playback-state-audit-2026-10-20/AUDIT.md` из артефактов задачи.

## Что исправлено

| Сценарий | Новое поведение |
| --- | --- |
| F5: drag начат на A, до отпускания выбран B | Контекст сессии/трека фиксируется при MouseDown; смена контекста отменяет drag, B не получает seek |
| F4: ответ seek A пришёл уже после выбора B | Ответ проверяется по context revision, ссылке на сессию и номеру seek; поздний ответ не меняет позицию B |
| Два seek одного трека завершились в обратном порядке | Только последний запрос может опубликовать позицию |
| F2: источник сменился, метаданные ещё не готовы | Старый снимок очищается сразу; показан нейтральный loading, transport/seek выключены до готовности нового снимка |
| F3: одинаковое название, другой источник/исполнитель и нет thumbnail | Чужая обложка/палитра не наследуются; идентичность не определяется одним title |
| F7: чтение playback-статуса завершилось ошибкой | Состояние unknown не заменяет известное Playing; восстановление не создаёт ложный старт |
| F9: ошибка провайдера при резервном опросе | Ошибка ловится внутри итерации, повтор через секунду; сам монитор продолжает работать |
| F6: во время сигнала таймера приходит Volume/Toast/Charge/Focus | Тревога сохраняет представление и свой срок; автоматическое сворачивание её не гасит |
| F1: вручную выбранный плеер закрыт | Снимается только pin исчезнувшей сессии; выбор переходит к другому играющему источнику, без липкого Home |
| F8: открыть меню поверх уведомления и закрыть | Устаревший transient отменяется при открытии панели и не появляется повторно |

Явный выбор главной **не отменяется** новым воспроизведением. Перелистывание
не посылает плеерам Play/Pause/Next. Приоритет Home относительно компактного
таймера/OBS и отсутствие переключения только из-за fullscreen оставлены прежними.

## Контекст управления и публикации

`MediaService.ContextVersion` — монотонная revision. Она меняется при смене
сессии, уведомлении о смене метаданных/трека и закрытии сервиса. Управление
разрешено только после `_ready`; до этого `CaptureContext()` возвращает -1.
`Seek(fraction, context)` проверяет context до отправки и после каждого await.
Номер запроса защищает от ответов предыдущего seek внутри того же трека.

При смене источника сразу очищаются title, artist, art/palette, старые timeline
и fallback-данные. Затем native playback/timeline относятся уже к новому
источнику. Metainfo и готовность публикуются вместе; обложка догружается отдельно
с version-guard и не задерживает transport. Для метаданных и обложки задан
трёхсекундный deadline/cancellation. После ошибки метаданные перечитываются
резервным опросом, без восстановления старых данных и кнопок.

MPC-BE native timeline сохраняет проверки source/title/context. Telegram
fallback-чтение и seek сериализованы отдельным lock на worker-потоках;
WPF Dispatcher этот lock не захватывает. Вызовы готового SMTC transport не
получили новых файловых/сетевых зависимостей.

## Наблюдение за проигрыванием

- `PlaybackActivity.Report` принимает bool?; null означает неизвестное состояние.
- Playback callbacks снимают статус до постановки в Dispatcher. Очередь таких
  наблюдений обрабатывается перед polling и перед ручным выбором страницы.
  Так сохраняются опубликованные быстрые pause/resume-переходы, а старые
  queued-события не отнимают более новый ручной выбор.
- Polling статусов сохраняет прежние 250/1000 мс. Список сессий дополнительно
  сверяется раз в секунду, чтобы обнаруживать новые источники и при пропущенном
  manager-событии. Порядок уже известных страниц сохраняется.
- Сбой current-session pointer не обнуляет здоровую сессию; остаются fallback
  по активности и известному списку.
- `MediaService.Dispose` отменяет мониторы, отключает подписки и инвалидирует
  контекст. Закрытое окно не принимает отложенные данные и не отправляет команды.

Не обещается восстановление паузы, которую провайдер вообще не опубликовал
или callback уже получил только конечное Playing. Плеер без SMTC-сессии по-прежнему
не появляется в списке; общий аудиоспектр не заменяет идентификацию источника.
Системный fullscreen/кинорежим, погода и экран Codex не переработаны.

## Проверки и отдельная тестовая граница

Обычная сборка и прежние тесты используют **настоящие WinRT-типы**:

```powershell
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release
```

Детерминированные сценарии включаются отдельно:

```powershell
dotnet run --project Tests/DynamicIsland.Tests.csproj -c Release -p:MediaTestApi=true -- --media-regressions
```

В этом режиме меняются только compile-time alias Manager/Session, а тела
методов MediaService/MainWindow — те же, что в production. Test doubles из
`Tests/Fakes` включены только условным ItemGroup; выходы и obj разделены
с нормальной сборкой. В обычном DLL/EXE этих типов нет — отдельная проверка
assert-ит их отсутствие. Установки пакетов для тестовых mock framework нет.

Сценарии покрывают все найденные дефекты, старый Telegram-paused → video-started
при устаревшем current Windows, отсутствие команд при перелистывании, явный
Home, исчезновение всех сессий/возврат новой, поздние и зависшие метаданные,
очередь pause/resume, повтор после исключения и завершение монитора.
Реальные пользовательские плееры, реальная тревога, Codex inference и реестр
для этих тестов не затрагиваются. Это не live-проверка каждого провайдера Windows.

Production publish, без MediaTestApi:

```powershell
dotnet publish DynamicIsland.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish/playback-fixed
```
