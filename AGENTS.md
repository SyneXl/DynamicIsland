# Правила работы с проектом

## Публикация обновлений

- Сначала реализовать изменения, выполнить проверки и собрать локальный EXE для проверки пользователем. В результате сообщить путь к сборке и кратко описать изменения.
- Публиковать обновление на GitHub только после отдельного явного разрешения пользователя на релиз проверенных изменений.
- Запросы «исправь», «реализуй», «продолжай» и разрешения на предыдущие релизы не являются разрешением на новый релиз.
- До такого разрешения не создавать и не отправлять версионные теги, не запускать workflow `Release`, не создавать релизы/черновики/prerelease и не загружать релизные файлы. Отправка тега `v*` автоматически запускает публикацию — это тоже требует разрешения.
- Не публиковать релиз автоматически в конце работы. Дождаться, пока пользователь проверит локальную сборку и разрешит публикацию.
